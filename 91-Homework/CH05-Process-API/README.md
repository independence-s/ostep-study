# CH05 · Interlude: Process API

> 教材第 5 章 · 作者仓库对应目录 `cpu-api/`

## 本章要回答的问题

1. `fork()` 创建的新进程，在进程树里挂到哪个父进程下？
2. 进程 `exit()` 之后，它**已经创建的子进程**去哪了？

这两件事决定了整棵进程树如何逐步演化。想清楚它们，`fork` 的行为就没有悬念了。

## 模拟器速查：`fork.py`

给定一串 fork / exit 动作，推出每一步的进程树。

```sh
cd ~/ostep-homework/cpu-api
./fork.py                  # 随机出题
./fork.py -s 20            # 指定种子，结果可复现
./fork.py -s 20 -c         # -c 显示答案
./fork.py -A a+b,b+c,c-    # 手动指定动作序列
```

动作语法：`a+b` 表示 a forks b；`b-` 表示 b 退出。

| 选项 | 作用 |
|---|---|
| `-s N` | 随机种子，同种子必得同题 |
| `-A <list>` | 手动指定动作序列，替代随机生成 |
| `-c` | 计算并显示答案 |
| `-F` | 只显示最终树（适合一次性推到底的自测） |
| `-t` | 反向题：给出树，猜动作 |
| `-f 0.7` | fork 动作占比（默认 0.7） |
| `-a N` | 动作总数（默认 5） |
| `-L` | 只有叶子进程能退出，否则报 `failed: has children` |
| `-R` | 退出后子进程挂到"就近"的父进程 |
| `-P fancy` | 打印风格：`basic` / `line1` / `line2` / `fancy` |

## 三步法

每个实验都按这个顺序写，**先预测再看答案**：

| 步骤 | 做什么 |
|---|---|
| 1 · Prediction | 只运行不带 `-c` 的版本，在纸上/表格里手写每一步的树 |
| 2 · Result | 加 `-c` 运行，与预测逐行对照 |
| 3 · Explanation | 找出预测错的那一步，说清为什么错 |

## 已实测的行为（易错点）

**非叶子进程退出时，它的子进程去哪？**

用 `./fork.py -A a+b,b+c,c+d,c- -c` 实测对比：

```text
默认模式：d 挂到【根】a 下        加 -R：d 挂到【c 的父】b 下

      a                                a
      ├── b                            └── b
      └── d                                └── d
```

而加 `-L` 会直接**禁止**这种退出：

```text
Action: c EXITS (failed: has children)
```

> 结论：默认是"提升到根"，`-R` 是"就近收养"，`-L` 是"不许走"。

**另一个坑：树的打印顺序**

兄弟节点的排列反映的是**创建先后**，不是字母顺序。中途退出的进程腾出的位置不会被子进程复用。
